## Medium

### M1. 자동 읽기 중 단어를 누르면 진행이 멈추거나 단어 읽기가 중간에 끊김

- 위치: `index.html:745`, `index.html:747`, `index.html:753`.
- 재현 A: 사자와 쥐 첫 장에서 Read All → 장면을 읽는 중 `A`를 누릅니다. 원본 코드 모의 실행에서 10초 진행 후에도 첫 장 문장이 그대로이고, `auto === true`, 예약 타이머 0개였습니다.

- 재현 B: 장면 읽기가 끝나고 다음 페이지까지 기다리는 1.8초 안에 단어를 누릅니다. 모의 실행에서 기존 자동 넘김 타이머가 살아 있어 다음 장으로 이동했습니다.
- 영향: 같은 단어 조작의 결과가 누른 시점에 따라 달라집니다. 아이가 단어를 다시 듣다가 자동 읽기가 멎거나 다음 장 음성으로 바뀔 수 있습니다.
- 제안: 단어 읽기를 시작하기 전에 자동 진행과 예약 콜백을 무효화하고 버튼 표시도 갱신합니다. 현재 `pause()`를 공통으로 쓰는 방식이 작게 고칠 수 있는 방법입니다.

```js

  pause();
  speak(sp.dataset.w.replace(/[^\w']/g, ""), {rate: .7});
});
```

- 영향: 사용자가 중단이라고 이해한 조작이 자동 재생을 다시 켭니다.
- 제안: Read·Slow에서도 기존 `pause()`를 사용하여 내부 상태와 버튼 문구·스타일을 함께 갱신합니다. M1과 같은 공통 중단 함수를 쓰면 동작을 일관되게 만들 수 있습니다.

### M3. 한국어 표시 전환이 재생 중인 하이라이트를 화면에서 분리함

## 실제 기기에서 남은 검증

- iPad·iPhone Safari에서 Read All의 첫 재생, 여러 클립 연결, 영상 시작 후 지연 재생, 음성 합성 대체를 확인해야 합니다. 현재 코드는 Read All 첫 재생을 700ms 후, 영상 첫 장면 음성을 제목 대기와 장면 대기 후 호출하므로 사용자 입력과 실제 오디오 시작이 떨어져 있습니다. 특정 iOS 버전에서 실패한다고 단정하지는 않습니다.
- iPhone의 전체 화면 요청 지원 여부와 시스템 전체 화면 종료 동작, 외장 키보드 없는 상황의 영상 종료를 확인해야 합니다. 터치 종료 컨트롤 부재 자체는 H2에서 확인했습니다.
- 음성 파형·파일 구조 검사는 실제 발음, 배역 연기, 영어·한국어 자막의 정확한 오디오 일치 여부를 보장하지 않습니다. 전체 179개를 청취한 검사는 아닙니다.
- PWA의 manifest·아이콘 경로와 치수는 확인했지만 실제 iOS 홈 화면 설치와 오프라인 사용은 검증하지 않았습니다.
